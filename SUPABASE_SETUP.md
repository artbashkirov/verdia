# Инструкция по настройке Supabase для проекта Verdia

## Шаг 1: Создание проекта в Supabase

1. Перейдите на [supabase.com](https://supabase.com)
2. Войдите в свой аккаунт или зарегистрируйтесь
3. Нажмите **"New Project"**
4. Заполните данные проекта:
   - **Name**: название проекта (например, "verdia")
   - **Database Password**: придумайте надежный пароль (сохраните его!)
   - **Region**: выберите ближайший регион
5. Нажмите **"Create new project"** и дождитесь создания (обычно 1-2 минуты)

## Шаг 2: Получение API ключей

1. В панели управления проекта перейдите в **Settings** (шестеренка внизу слева)
2. Выберите **API** в меню настроек
3. Скопируйте следующие значения:
   - **Project URL** → это будет `NEXT_PUBLIC_SUPABASE_URL`
   - **anon public** ключ → это будет `NEXT_PUBLIC_SUPABASE_ANON_KEY`

## Шаг 3: Настройка базы данных

1. В панели управления перейдите в **SQL Editor** (иконка базы данных в левом меню)
2. Откройте файл `supabase/schema.sql` из проекта
3. Скопируйте **весь** содержимое файла
4. Вставьте в SQL Editor в Supabase
5. Нажмите **"Run"** (или `Cmd/Ctrl + Enter`)

Это создаст:
- Таблицы: `users`, `generations`, `chat_history`, `chat_messages`
- Индексы для оптимизации запросов
- Row Level Security (RLS) политики
- Триггеры для автоматического создания профилей пользователей
- Функции для обновления временных меток

## Шаг 4: Настройка аутентификации

### 4.1. Настройка URL Configuration

**ВАЖНО**: Эти настройки критичны для правильной работы подтверждения регистрации по email!

1. Перейдите в **Authentication** → **URL Configuration**
2. В поле **Site URL** установите:
   - Для разработки: `http://localhost:3000`
   - Для production: `https://ai-verdia.ru` (или ваш production домен)
3. В разделе **Redirect URLs** добавьте (можно несколько, каждую с новой строки):
   - Для разработки: `http://localhost:3000/auth/callback`
   - Для production: `https://ai-verdia.ru/auth/callback` (или ваш production домен)
4. Нажмите **"Save"**

**Примечание**: Если после подтверждения регистрации вас перенаправляет на localhost вместо production домена, проверьте, что **Site URL** установлен на правильный production домен!

### 4.2. Настройка Email (опционально, но рекомендуется)

1. Перейдите в **Authentication** → **Email Templates**
2. При необходимости настройте шаблоны писем:
   - **Confirm signup** - подтверждение регистрации
   - **Reset password** - сброс пароля
   - **Magic Link** - вход по ссылке (если используется)

### 4.3. Настройка Email Provider (ОБЯЗАТЕЛЬНО для production!)

**Важно**: На бесплатном плане Supabase встроенный SMTP часто не работает или имеет очень строгие лимиты. Для production **обязательно** нужно настроить собственный SMTP!

#### Вариант 1: Настройка через Gmail (бесплатно, рекомендуется для начала)

1. Перейдите в **Project Settings** → **Auth** → **SMTP Settings**
2. Включите **"Enable Custom SMTP"**
3. Заполните настройки:
   - **Sender email**: ваш Gmail адрес (например, `your-email@gmail.com`)
   - **Sender name**: название отправителя (например, "Verdia")
   - **Host**: `smtp.gmail.com`
   - **Port**: `587`
   - **Username**: ваш Gmail адрес
   - **Password**: **НЕ ваш обычный пароль!** Нужно создать "Пароль приложения":
     - Перейдите в [Google Account Security](https://myaccount.google.com/security)
     - Включите 2-Step Verification (если не включено)
     - Перейдите в "App passwords" → создайте новый пароль для "Mail"
     - Используйте этот 16-символьный пароль в настройках SMTP
   - **Secure**: включите (TLS)
4. Нажмите **"Save"**
5. Протестируйте отправку письма

#### Вариант 2: Настройка через Yandex SMTP (рекомендуется для РФ!)

**Лучший выбор для российских проектов** - бесплатно, надежно, не будет заблокирован.

1. Создайте почтовый ящик на [Yandex](https://mail.yandex.ru) (если нет)
2. Включите пароль приложения:
   - Перейдите в [Yandex ID](https://id.yandex.ru/security)
   - Включите двухфакторную аутентификацию (если не включена)
   - Перейдите в "Пароли приложений" → создайте новый пароль для "Почта"
   - Скопируйте пароль (16 символов)
3. В Supabase: **Project Settings** → **Auth** → **SMTP Settings**
4. Включите **"Enable Custom SMTP"**
5. Заполните настройки (попробуйте оба варианта по очереди):

   **Вариант A: Порт 587 с TLS (рекомендуется сначала):**
   - **Host**: `smtp.yandex.ru`
   - **Port**: `587`
   - **Username**: ваш полный email на Yandex (например, `your-email@yandex.ru`)
   - **Password**: пароль приложения из шага 2 (НЕ обычный пароль!)
   - **Sender email**: ваш Yandex email
   - **Sender name**: `Verdia`
   - **Secure**: автоматически TLS для порта 587

   **Вариант B: Порт 465 с SSL (если 587 не работает):**
   - **Host**: `smtp.yandex.ru`
   - **Port**: `465`
   - **Username**: ваш полный email на Yandex
   - **Password**: пароль приложения
   - **Sender email**: ваш Yandex email
   - **Sender name**: `Verdia`
   - **Secure**: автоматически SSL для порта 465

6. Нажмите **"Save"**
7. Протестируйте отправку

**Лимиты**: до 1000 писем в день на бесплатном аккаунте Yandex.

**Устранение проблем с Yandex SMTP:**

Если получаете ошибки 500 или 504:

1. **Проверьте пароль приложения:**
   - Убедитесь, что используете пароль приложения (16 символов), а не обычный пароль
   - Пароль должен быть создан специально для "Почта"
   - Если сомневаетесь - создайте новый пароль приложения

2. **Попробуйте разные порты:**
   - Сначала попробуйте порт `587` (TLS)
   - Если не работает - попробуйте порт `465` (SSL)

3. **Проверьте настройки безопасности Yandex:**
   - Убедитесь, что двухфакторная аутентификация включена
   - Проверьте, нет ли блокировок в разделе "Безопасность"
   - Проверьте почту на наличие уведомлений о подозрительной активности

4. **Проверьте логи в Supabase:**
   - Logs → Auth Logs
   - Ищите ошибки типа "SMTP connection failed", "authentication failed"
   - Ошибка 504 = таймаут подключения к SMTP
   - Ошибка 500 = ошибка аутентификации или отправки

5. **Если ничего не помогает:**
   - Попробуйте Mail.ru SMTP (см. Вариант 3)
   - Или временно отключите подтверждение email для тестирования

#### Вариант 3: Настройка через Mail.ru SMTP (альтернатива для РФ)

1. Создайте почтовый ящик на [Mail.ru](https://mail.ru) (если нет)
2. Включите пароль приложения:
   - Перейдите в [Настройки безопасности Mail.ru](https://id.mail.ru/profile)
   - Включите двухфакторную аутентификацию
   - Создайте пароль приложения для "Почта"
3. В Supabase: **Project Settings** → **Auth** → **SMTP Settings**
4. Включите **"Enable Custom SMTP"**
5. Заполните:
   - **Host**: `smtp.mail.ru`
   - **Port**: `465` (или `587` с TLS)
   - **Username**: ваш полный email на Mail.ru
   - **Password**: пароль приложения
   - **Sender email**: ваш Mail.ru email
   - **Sender name**: `Verdia`
   - **Secure**: включите (SSL/TLS)
6. Нажмите **"Save"**

#### Вариант 4: Настройка через Resend (РЕКОМЕНДУЕТСЯ для Supabase!)

**Лучший выбор для работы с Supabase** - создан специально для разработчиков, отличная интеграция.

**Преимущества:**
- Бесплатный план: 3000 писем/месяц, 100 писем/день
- Отличная доставляемость
- Простая настройка
- Хорошая документация
- Популярен среди разработчиков

**Настройка:**

1. Зарегистрируйтесь на [Resend](https://resend.com) (бесплатно)
2. Верифицируйте ваш email
3. Создайте API ключ:
   - Dashboard → API Keys → Create API Key
   - Название: "Supabase SMTP"
   - Скопируйте ключ (показывается один раз)
4. Добавьте домен (опционально, можно использовать их домен для тестирования)
5. В Supabase: **Project Settings** → **Auth** → **SMTP Settings**
6. Включите **"Enable Custom SMTP"**
7. Заполните:
   - **Host**: `smtp.resend.com`
   - **Port**: `587`
   - **Username**: `resend`
   - **Password**: ваш Resend API ключ
   - **Sender email**: ваш верифицированный email в Resend (или домен, если добавили)
   - **Sender name**: `Verdia`
   - **Secure**: автоматически TLS для порта 587
8. Нажмите **"Save"**

**Лимиты**: 3000 писем/месяц на бесплатном плане.

#### Вариант 5: Настройка через SendGrid (для международных проектов)

**Преимущества:**
- Бесплатный план: 100 писем/день
- Надежный сервис
- Хорошая доставляемость

**Настройка:**

1. Зарегистрируйтесь на [SendGrid](https://sendgrid.com) (бесплатный план: 100 писем/день)
2. Верифицируйте ваш email
3. Создайте API ключ:
   - Settings → API Keys → Create API Key
   - Название: "Supabase SMTP"
   - Permissions: "Mail Send" → "Full Access"
   - Скопируйте ключ (показывается один раз)
4. В Supabase: **Project Settings** → **Auth** → **SMTP Settings**
5. Включите **"Enable Custom SMTP"**
6. Заполните:
   - **Host**: `smtp.sendgrid.net`
   - **Port**: `587`
   - **Username**: `apikey`
   - **Password**: ваш SendGrid API ключ
   - **Sender email**: ваш верифицированный email в SendGrid
   - **Sender name**: `Verdia`
   - **Secure**: автоматически TLS для порта 587
7. Нажмите **"Save"**

**Лимиты**: 100 писем/день на бесплатном плане.

2. Добавьте следующие переменные:

```env

NEXT_PUBLIC_SUPABASE_ANON_KEY=ваш_anon_ключ_из_шага_2
```

**Важно**: 
- Замените `https://ваш-проект.supabase.co` на реальный URL из шага 2
- Замените `ваш_anon_ключ_из_шага_2` на реальный ключ из шага 2

## Шаг 6: Проверка настройки

### 6.1. Проверка подключения

Запустите в терминале:
```bash
npm run check-supabase
```

Если все настроено правильно, вы увидите сообщение об успешном подключении.

### 6.2. Проверка базы данных

1. В Supabase перейдите в **Table Editor**
2. Убедитесь, что созданы таблицы:
   - `users`
   - `generations`
   - `chat_history`
   - `chat_messages`

### 6.3. Проверка RLS политик

1. В Supabase перейдите в **Authentication** → **Policies**
2. Убедитесь, что для каждой таблицы созданы политики:
   - `users`: SELECT, UPDATE, INSERT (только для своего профиля)
   - `generations`: SELECT, INSERT, DELETE (только свои)
   - `chat_history`: SELECT, INSERT, UPDATE, DELETE (только свои)
   - `chat_messages`: SELECT, INSERT, DELETE (только свои)

## Возможные проблемы и решения

### Проблема: "Invalid Supabase URL format"
**Решение**: Проверьте, что в `.env.local` указан полный URL (начинается с `https://`)

### Проблема: "Missing Supabase environment variables"
**Решение**: 
- Убедитесь, что файл `.env.local` существует в корне проекта
- Проверьте, что переменные названы правильно (без опечаток)
- Перезапустите dev сервер после изменения `.env.local`

### Проблема: "Email не приходит на почту"
**Решение** (проверьте по порядку):

1. **Проверьте, что Email провайдер включен:**
   - Перейдите в **Authentication** → **Providers** → **Email**
   - Убедитесь, что переключатель **"Enable Email Provider"** включен
   - Проверьте, что **"Confirm email"** включен (если требуется подтверждение)

2. **Проверьте настройки SMTP:**
   - Перейдите в **Project Settings** → **Auth** → **SMTP Settings**
   - Если используете встроенный SMTP Supabase (бесплатный план):
     - Убедитесь, что он включен
     - **Важно**: На бесплатном плане Supabase есть лимиты на отправку email (около 3-4 писем в час)
   - Для production рекомендуется настроить собственный SMTP (Gmail, SendGrid, Mailgun)

3. **Проверьте логи в Supabase:**
   - Перейдите в **Logs** → **Auth Logs**
   - Найдите записи о попытке отправки email
   - Проверьте, есть ли ошибки

4. **Проверьте папку Спам:**
   - Письма от Supabase могут попадать в спам
   - Проверьте папку "Спам" или "Junk" в вашем почтовом ящике

5. **Проверьте лимиты бесплатного плана:**
   - На бесплатном плане Supabase есть ограничения на отправку email
   - Если превышен лимит, письма не будут отправляться до сброса лимита

6. **Для production - настройте собственный SMTP:**
   - Рекомендуется использовать Gmail, SendGrid, Mailgun или другой SMTP сервис
   - Настройте в **Project Settings** → **Auth** → **SMTP Settings**

### Проблема: "Users can't register"
**Решение**:
- Проверьте, что в Supabase включена регистрация: **Authentication** → **Providers** → **Email** → включен
- Проверьте Redirect URLs (шаг 4.1)
- Проверьте, что схема базы данных применена (шаг 3)

### Проблема: "RLS policy violation"
**Решение**:
- Убедитесь, что все RLS политики созданы (проверьте шаг 3)
- Проверьте, что пользователь авторизован
- В Table Editor проверьте, что политики активны

### Проблема: "Trigger doesn't work"
**Решение**:
- Убедитесь, что функция `handle_new_user()` создана
- Проверьте, что триггер `on_auth_user_created` активен
- Проверьте логи в Supabase: **Logs** → **Postgres Logs**

## Важные замечания

1. **Безопасность**: Никогда не коммитьте `.env.local` в git. Он уже должен быть в `.gitignore`
2. **Production**: Для production используйте переменные окружения на VPS (в .env или через PM2/systemd)
3. **Backup**: Регулярно делайте бэкапы базы данных через Supabase Dashboard
4. **Мониторинг**: Используйте **Logs** в Supabase для отслеживания ошибок
