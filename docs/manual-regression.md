# Чек-лист ручной регрессии

Прогонять перед каждым релизом. Минимум — на трёх средах:
**Desktop Chrome (Mac)**, **iOS Safari** (физический iPhone), **Android Chrome** (физический Android).
Желательно дополнительно: PWA-режим («Добавить на главный экран») и встроенный
WebView Telegram/VK (если есть пользователи оттуда).

> Каждый сценарий проходим до конца. Если что-то упало — фиксируем баг,
> добавляем регресс-тест перед фиксом.

---

## 1. Авторизация

- [ ] Регистрация по email + пароль → пришло письмо → подтверждение → попадаем в `/chat`.
- [ ] Логин с правильным паролем → попадаем в `/chat`.
- [ ] Логин с неверным паролем → показывается ошибка, не пускает.
- [ ] Forgot password → пришло письмо → reset → новый пароль работает.
- [ ] Logout → редирект на `/login`, sidebar чист.
- [ ] Открытие `/chat` без сессии → редирект на `/login`.
- [ ] Открытие `/login` с активной сессией → редирект на `/chat`.

## 2. История чатов (sidebar)

- [ ] Список загружается за < 2 секунды.
- [ ] При обрыве сети sidebar показывает кэшированный список (localStorage).
- [ ] После создания нового чата он появляется в sidebar в реальном времени (realtime).
- [ ] При переключении между чатами content корректно подгружается.
- [ ] Удаление чата работает; если удалили текущий — редирект на `/chat`.
- [ ] «Очистить историю» работает и не падает.

## 3. Открытие сохранённого чата

- [ ] Открываем чат из sidebar → загружается за < 3 секунд.
- [ ] При плохой сети (Throttle: Slow 3G) — лоадер крутится, потом контент или явная ошибка.
- [ ] При истёкшей сессии → редирект на `/login` (а не «зависание»).
- [ ] **Не должно мигать** «Результат не найден», пока чат ещё грузится.
- [ ] Если чата нет в БД — показывается явное «Результат не найден» с кнопкой «Новый запрос».

## 4. Новый запрос → генерация → ответ

- [ ] На `/chat` ввели вопрос → нажали Отправить → перешли на `/chat/[id]`.
- [ ] Виден лоадер «Ищу судебные дела…», затем карточки дел.
- [ ] Виден ответ: краткий, правовой анализ, практика, рекомендации.
- [ ] Поллинг работает: если генерация идёт долго, ответ дотягивается без перезагрузки.
- [ ] Если backend упал во время генерации — пользователь видит понятную ошибку.

## 5. Скачивание документов (КРИТИЧНО для Android)

- [ ] Открываем чат с готовыми документами.
- [ ] Клик по карточке документа → файл `.docx` скачивается.
- [ ] **На Android Chrome**: скачивание реально проходит (файл появился в Downloads).
- [ ] **На iOS Safari**: открывается «Поделиться/Сохранить файл».
- [ ] Кнопка «Скачать все» скачивает все документы по очереди.
- [ ] При ошибке генерации DOCX — fallback на `.txt`.
- [ ] Скачивание из чата (после «Составь иск») тоже работает на Android.

## 6. Чат-продолжение (после ответа)

- [ ] «Составь исковое заявление» / «Составь претензию» → приходит документ.
- [ ] Сообщения сохраняются после перезагрузки страницы.
- [ ] Двойной клик / двойная отправка не создаёт двойное сообщение.
- [ ] При обрыве сети — внятная ошибка, исчезает оптимистичное сообщение.

## 7. Профиль

- [ ] Загрузка профиля за < 2 секунды.
- [ ] Сохранение всех типов лица: physical, ИП, юрлицо.
- [ ] При истёкшей сессии — редирект на `/login`.
- [ ] При плохой сети — кнопка «Сохранить» либо проходит, либо явная ошибка.

## 8. Mobile-specific UI

- [ ] **iOS Safari**: ChatInput не уезжает за нижнюю панель браузера.
- [ ] **iOS Safari**: при появлении клавиатуры инпут видно, контент скроллится корректно.
- [ ] **Android Chrome**: то же самое, плюс корректная работа при swipe-up жесте.
- [ ] **Yandex Browser** (если используется): не ломается viewport.
- [ ] Поворот экрана iPhone/Android → layout адаптируется.
- [ ] PWA (добавлено на домашний экран) → запуск из иконки работает, нет лишних баров.

## 9. Сеть и edge cases

- [ ] Открыли вкладку, отключили сеть, кликаем по чатам → понятная ошибка.
- [ ] Открыли вкладку, оставили на 30+ минут, вернулись → клики работают
      (либо явный ре-логин, не зависание).
- [ ] Открыли две вкладки одновременно → работают независимо, sidebar
      синхронизируется через realtime.
- [ ] После деплоя — старая открытая вкладка не должна крашиться (graceful refresh).

## 11. Поведение во время деплоя / падения upstream

### 11.1. Базовые проверки (актуальны всегда)

- [ ] `GET /api/health` отвечает 200 OK с `{ status: "ok", uptime, timestamp }`,
      когда сервис жив; и не блокирует основной флоу при падении (см.
      `docs/nginx-config.md` — health не должен попадать под `error_page`).
- [ ] При падении ВСЕХ upstream'ов (`pm2 stop verdia-blue verdia-green`)
      открытие любого URL сайта показывает нашу страницу `502.html`
      («Сервис обновляется»), а **не** дефолтный nginx 502.
- [ ] Страница `502.html` сама обновляется в течение ~4–8 секунд после
      того, как pm2 поднял сервис обратно (без ручного refresh).
- [ ] В GitHub Actions при сломанном билде шаг `build-check` падает раньше
      деплоя — VPS не получает поломанный код.
- [ ] В GitHub Actions при упавшем healthcheck после reload — шаг deploy
      падает с понятным логом (`pm2 logs verdia-{blue,green} --lines 50`).

### 11.2. Blue-green failover (после миграции — `docs/migration-blue-green.md`)

- [ ] **Failover blue → green:** `pm2 stop verdia-blue` → сайт продолжает
      работать без 502 (трафик на green:3002), `curl -I https://ai-verdia.ru/`
      отдаёт 200. Восстановить: `pm2 start verdia-blue`.
- [ ] **Failover green → blue:** аналогично с `pm2 stop verdia-green`.
- [ ] **Rolling deploy при открытом сайте:** пушим коммит в `main`,
      во время деплоя:
      - открытая страница не должна сломаться (graceful shutdown,
        `kill_timeout: 10s`);
      - refresh во время `pm2 reload verdia-blue` → green обслуживает
        (response < 1 сек);
      - refresh во время `pm2 reload verdia-green` → blue обслуживает;
      - **в сумме за весь цикл деплоя — ни одного 502** (убедиться в
        DevTools → Network: все запросы 200).
- [ ] **Fail-fast при поломанной новой версии:** если новый код не
      поднимается на blue (например, ошибка в build), Actions фейлит
      деплой ДО того, как трогает green. Зелёный остаётся на старой
      версии. Сайт продолжает работать (одним инстансом).
- [ ] **Логи Actions показывают**: `Step 1: reload verdia-blue` →
      `[verdia-blue] healthcheck OK` → `Step 2: reload verdia-green` →
      `[verdia-green] healthcheck OK` → `✅ Deploy complete (zero-downtime)`.

### 11.3. Защита от ChunkLoadError при деплое

Контекст: при `npm run build` Next.js пересоздаёт `.next/static/` с новыми
именами чанков. У пользователя с открытой вкладкой SPA пытается догрузить
старый чанк → 404 → сломанный экран без CSS/JS. Защита двухслойная:
сервер хранит архив старых чанков 14 дней + клиент ловит ChunkLoadError
и делает auto-reload.

- [ ] **Архив сохраняется:** в логах Actions видно строки
      `[chunks] backup current .next/static → archive`,
      `[chunks] merge archive → .next/static`,
      `[chunks] archive size: ~XX MB`.
- [ ] **На VPS папка существует:** `ls -la /opt/verdia-app/.next-static-archive/`
      — должна быть, и в ней есть файлы. Размер растёт с каждым деплоем,
      но не больше нескольких сотен МБ (старше 14 дней удаляется).
- [ ] **Открытая до деплоя вкладка не ломается:** открыть сайт в браузере,
      запушить коммит в `main`, дождаться завершения деплоя, **продолжать
      использовать ту же вкладку** (нажимать на чаты, переключаться
      между разделами). Все чанки должны догружаться без ошибок,
      DevTools → Network: ни одного 404 на `_next/static/...`.
- [ ] **ChunkErrorRecovery работает:** в DevTools Console выполнить
      `throw new Error('Loading chunk 0 failed')` (имитация). Должна
      произойти автоматическая перезагрузка страницы. Повторный throw
      в течение 30 секунд reload не вызывает (anti-loop защита).
- [ ] **Очистка старых чанков:** через 14+ дней после первого деплоя
      `find /opt/verdia-app/.next-static-archive -type f -mtime +14 | wc -l`
      должно быть 0 (cleanup работает).

1. Зафиксировать в issue: устройство / браузер / версия / шаги воспроизведения.
2. **Сначала написать failing-тест** (юнит или e2e), потом фиксить.
3. Перед PR — повторно прогнать минимум этот один пункт чек-листа на iOS + Android.
