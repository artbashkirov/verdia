## 🔄 Цепочка запроса пользователя

### 1. Пользователь открывает сайт

```
Пользователь → Браузер → https://ai-verdia.ru
```

**Что происходит:**
- Браузер выполняет DNS lookup: `ai-verdia.ru` → `193.227.240.206`
- Устанавливает HTTPS соединение (порт 443)

### 2. DNS и маршрутизация

```
Браузер → DNS сервер (REG.RU) → IP: 193.227.240.206
```

**Технологии:**
- **DNS** (Domain Name System) — преобразует домен в IP адрес
- **REG.RU** — DNS провайдер, управляет DNS записями

**DNS записи:**
- `A @ → 193.227.240.206` (корневой домен)
- `A www → 193.227.240.206` (поддомен www)

### 3. Nginx получает запрос

```
HTTPS запрос (порт 443) → Nginx на VPS
```

**Что делает Nginx:**
1. Принимает HTTPS запрос на порту 443
2. Проверяет SSL сертификат (Let's Encrypt)
3. Дешифрует HTTPS → HTTP
4. Проксирует запрос на `http://localhost:3000`

**Конфигурация Nginx:**
```nginx
server {
    listen 443 ssl http2;
    server_name ai-verdia.ru;
    
    # SSL сертификаты
    ssl_certificate /etc/letsencrypt/live/ai-verdia.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ai-verdia.ru/privkey.pem;
    
    # Проксирование на Next.js
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # ... другие заголовки
    }
}
```

**Почему нужен Nginx:**
- Стандартные порты (80/443) для пользователей
- SSL/TLS обработка (HTTPS)
- Защита приложения (приложение не доступно напрямую)
- Оптимизация (кеширование, сжатие)

### 4. PM2 управляет процессом

```
Nginx → localhost:3000 → PM2 → Node.js процесс
```

**Что делает PM2:**
- Управляет процессом Node.js приложения
- Обеспечивает автоперезапуск при падении
- Логирование
- Мониторинг (CPU, память)

**Конфигурация PM2 (`ecosystem.config.js`):**
```javascript
{
  name: 'verdia',
  script: './start.sh',  // Скрипт запуска
  cwd: '/opt/verdia-app',
  instances: 1,
  autorestart: true,     // Автоперезапуск
  max_restarts: 10,      // Максимум перезапусков
}
```

**Почему нужен PM2:**
- Без PM2: процесс остановится при падении или закрытии терминала
- С PM2: автоматический перезапуск, работа в фоне, логи

### 5. Node.js выполняет код

```
PM2 → Node.js → Выполняет JavaScript код
```

**Что делает Node.js:**
- Выполняет JavaScript код на сервере (не в браузере)
- Обрабатывает HTTP запросы
- Выполняет Next.js приложение

**Почему нужен Node.js:**
- Next.js требует Node.js для работы
- Next.js — это фреймворк на Node.js
- Node.js выполняет серверный код (API routes, SSR)

### 6. Next.js обрабатывает запрос

```
Node.js → Next.js → Обрабатывает запрос
```

**Что делает Next.js:**

#### A. Страницы (Pages)
- **Server Components** — рендерит HTML на сервере
- **Client Components** — интерактивные компоненты
- **SSR (Server-Side Rendering)** — генерирует HTML при каждом запросе

#### B. API Routes (`/api/*`)
- Обрабатывает HTTP запросы (GET, POST, etc.)
- Выполняет бизнес-логику
- Возвращает JSON или другие данные

**Пример API Route:**
```typescript
// src/app/api/chat/route.ts
export async function POST(request: Request) {
  // 1. Получает данные из запроса
  const body = await request.json();
  
  // 2. Вызывает AI (Gemini по умолчанию или OpenAI)
  const response = await chatCompletion([...]);
  
  // 3. Сохраняет в Supabase
  await supabase.from('generations').insert({...});
  
  // 4. Возвращает ответ
  return Response.json({ data: response });
}
```

### 7. Взаимодействие с внешними сервисами

#### A. Supabase (База данных)
```
Next.js API Route → Supabase Client → PostgreSQL
```

**Что делает:**
- Хранит данные пользователей
- Аутентификация (email/password)
- Row Level Security (RLS)

**Пример:**
```typescript
const { data, error } = await supabase
  .from('generations')
  .select('*')
  .eq('user_id', userId);
```

#### B. AI (Gemini — основная, OpenAI — опционально)
```
Next.js API Route → Gemini (через Cloudflare Worker) или OpenAI SDK
```

**Что делает:**
- Генерирует текстовые ответы (основная модель — Gemini)
- Анализирует юридические вопросы и иски
- Генерирует документы

#### C. VPS Scraper (Парсинг)
```
Next.js API Route → HTTP запрос → VPS Scraper (порт 3001)
```

**Что делает:**
- Парсит судебные решения
- Поиск по судебной практике

**Пример:**
```typescript
const response = await fetch('http://193.227.240.206:3001/search', {
  method: 'POST',
  body: JSON.stringify({ query: '...' }),
});
```

### 8. Ответ пользователю

```
Next.js → Node.js → PM2 → Nginx → HTTPS → Браузер → Пользователь
```

**Что происходит:**
- Next.js генерирует HTML или JSON
- Nginx добавляет заголовки безопасности
- Шифрует ответ (HTTPS)
- Отправляет в браузер
- Браузер отображает страницу

## 🚀 Цепочка деплоя

### 1. Разработчик делает изменения

```
Разработчик → Редактирует код → git commit → git push
```

**Технологии:**
- **Git** — система контроля версий
- **GitHub** — хостинг репозитория

### 2. GitHub получает push

```
git push origin main → GitHub репозиторий
```

**Что происходит:**
- Код попадает в GitHub
- GitHub триггерит GitHub Actions workflow

### 3. GitHub Actions запускается

```
GitHub → GitHub Actions Workflow → SSH на VPS
```

**Конфигурация (`.github/workflows/deploy.yml`):**
```yaml
name: Deploy to VPS

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest  # GitHub runner (только для SSH)
    
    steps:
      - name: Deploy to VPS
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.VPS_HOST }}  # 193.227.240.206
          username: root
          key: ${{ secrets.VPS_SSH_KEY }}
          script: |
            cd /opt/verdia-app
            git pull origin main
            npm install --production=false
            npm run build              # ⭐ СБОРКА НА VPS
            pm2 restart verdia
```

**Важно:**
- GitHub Actions runner только выполняет SSH команды
- Сборка происходит **НА VPS**, а не на GitHub runner
- Это экономит ресурсы GitHub и позволяет использовать ресурсы VPS

### 4. SSH подключение к VPS

```
GitHub Actions → SSH → VPS (193.227.240.206)
```

**Технологии:**
- **SSH** (Secure Shell) — безопасное подключение к серверу
- **SSH ключ** — аутентификация без пароля

### 5. Обновление кода на VPS

```
SSH → VPS → git pull origin main
```

**Что происходит:**
- Получает новый код из GitHub
- Обновляет файлы в `/opt/verdia-app`

### 6. Установка зависимостей

```
VPS → npm install
```

**Что происходит:**
- Устанавливает новые пакеты (если есть)
- Обновляет `node_modules`
- Использует `package.json` для определения зависимостей

**Зависимости:**
- **Production**: next, react, @supabase/supabase-js, openai (опционально), и др.
- **Dev**: typescript, eslint, tailwindcss, и др.

### 7. Сборка приложения

```
VPS → npm run build
```

**Что происходит:**
- **Next.js компилирует код:**
  - TypeScript → JavaScript
  - React компоненты → JavaScript
  - Оптимизирует код
  - Создает статические страницы (SSG)
  - Генерирует `.next` директорию

**Результат:**
- Собранное приложение готово к запуску
- Все файлы в `.next/`

### 8. Перезапуск приложения

```
VPS → pm2 restart verdia
```

**Что происходит:**
- PM2 останавливает старый процесс
- Запускает новый процесс с обновленным кодом
- Приложение обновлено без простоя

**Почему PM2:**
- Без PM2: нужно было бы вручную останавливать и запускать
- С PM2: одна команда для перезапуска

### 9. Приложение работает

```
PM2 → Node.js → Next.js → Приложение работает на порту 3000
```

**Результат:**
- Новый код работает
- Пользователи получают обновленную версию
- Без простоя (zero-downtime deployment)

## 📚 Технологии подробно

### Node.js

**Что это:** Среда выполнения JavaScript вне браузера.

**Роль в проекте:**
- Выполняет JavaScript код на сервере
- Требуется для Next.js (Next.js работает на Node.js)
- Обрабатывает HTTP запросы
- Выполняет серверный код (API routes, SSR)

**Почему важен:**
- Без Node.js Next.js не смог бы работать
- Next.js — это фреймворк на Node.js
- Node.js позволяет писать серверный код на JavaScript

**Аналогия:** Node.js = кухня ресторана, JavaScript = язык повара

### PM2

**Что это:** Process Manager 2 — менеджер процессов для Node.js.

**Роль в проекте:**
- Запускает Node.js процессы
- Управляет жизненным циклом приложения
- Автоматический перезапуск при падении
- Логирование
- Мониторинг (CPU, память)

**Конфигурация:**
```javascript
// ecosystem.config.js
{
  name: 'verdia',
  script: './start.sh',      // Скрипт запуска
  cwd: '/opt/verdia-app',    // Директория
  instances: 1,              // Количество процессов
  autorestart: true,         // Автоперезапуск
  max_restarts: 10,          // Максимум перезапусков
}
```

**Почему важен:**
- Без PM2: процесс остановится при падении или закрытии терминала
- С PM2: автоматический перезапуск, работа в фоне, удобные логи

**Основные команды:**
```bash
pm2 list              # Список процессов
pm2 restart verdia    # Перезапуск
pm2 logs verdia       # Логи
pm2 stop verdia       # Остановка
pm2 delete verdia     # Удаление
pm2 save              # Сохранить конфигурацию
```

### Nginx

**Что это:** Веб-сервер и reverse proxy.

**Роль в проекте:**
- Принимает HTTP/HTTPS запросы от пользователей
- Обрабатывает SSL/TLS (HTTPS)
- Проксирует запросы на Next.js приложение (порт 3000)
- Защищает приложение (приложение не доступно напрямую)
- Может кешировать статику

**Конфигурация:**
```nginx
server {
    listen 443 ssl http2;
    server_name ai-verdia.ru;
    
    # SSL сертификаты
    ssl_certificate /etc/letsencrypt/live/ai-verdia.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ai-verdia.ru/privkey.pem;
    
    # Проксирование на Next.js
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**Почему важен:**
- Стандартные порты (80/443) для пользователей
- SSL/TLS обработка (HTTPS)
- Защита приложения
- Профессиональная архитектура

**Без Nginx:**
- Пользователи должны были бы заходить на `https://ai-verdia.ru:3000`
- Нужно было бы настраивать SSL на Next.js

### Next.js

**Что это:** React-фреймворк для веб-приложений.

**Роль в проекте:**
- Создает пользовательский интерфейс (React компоненты)
- Обрабатывает HTTP запросы (API routes)
- Серверный рендеринг (SSR)
- Маршрутизация
- Оптимизация производительности

**Компоненты Next.js:**

1. **Pages (Страницы)**
   - Server Components — рендер на сервере
   - Client Components — интерактивность
   - SSR/SSG — генерация HTML

2. **API Routes (`/api/*`)**
   - Обработка HTTP запросов
   - Бизнес-логика
   - Взаимодействие с БД и внешними API

3. **Middleware**
   - Аутентификация
   - Редиректы
   - Защита роутов

**Почему важен:**
- Объединяет frontend и backend в одном проекте
- SSR для SEO
- Оптимизация производительности
- Удобная разработка

### Supabase

**Что это:** Backend-as-a-Service (BaaS), PostgreSQL база данных.

**Роль в проекте:**
- Хранит данные (пользователи, чаты, генерации)
- Аутентификация (email/password)
- Row Level Security (RLS)
- REST API автоматически

**Почему важен:**
- Не нужно настраивать базу данных самостоятельно
- Встроенная аутентификация
- Безопасность (RLS)
- Масштабируемость

### Gemini (основная AI) и OpenAI (опционально)

**Gemini** — основная нейросеть для анализа исков и генерации юридических ответов (через Cloudflare Worker / Replicate API).

**OpenAI** — опциональная альтернатива (GPT-4o и др.).

**Роль в проекте:**
- Генерация текстовых ответов
- Анализ юридических вопросов и исков
- Генерация документов

## 🎯 Итоговая схема

### Полный поток данных

```
1. ПОЛЬЗОВАТЕЛЬ
   ↓
2. DNS (ai-verdia.ru → 193.227.240.206)
   ↓
3. NGINX (порт 443, HTTPS)
   ↓
4. PM2 (управляет процессом)
   ↓
5. NODE.JS (выполняет код)
   ↓
6. NEXT.JS (обрабатывает запрос)
   ↓
7. ВНЕШНИЕ СЕРВИСЫ (Supabase, Gemini/OpenAI, и др.)
   ↓
8. ОТВЕТ → NEXT.JS → NODE.JS → PM2 → NGINX → БРАУЗЕР → ПОЛЬЗОВАТЕЛЬ
```

### Полный поток деплоя

```
1. РАЗРАБОТЧИК (git push)
   ↓
2. GITHUB (получает код)
   ↓
3. GITHUB ACTIONS (триггерит деплой)
   ↓
4. SSH на VPS (подключение)
   ↓
5. GIT PULL (обновление кода)
   ↓
6. NPM INSTALL (зависимости)
   ↓
7. NPM RUN BUILD (сборка)
   ↓
8. PM2 RESTART (перезапуск)
   ↓
9. ПРИЛОЖЕНИЕ РАБОТАЕТ (обновлено)
```

## 📊 Резюме

### Технологии и их роли

| Технология | Где работает | Роль |
|-----------|-------------|------|
| **Next.js** | VPS (порт 3000) | Веб-приложение |
| **Node.js** | VPS | Выполняет Next.js |
| **PM2** | VPS | Управляет Node.js процессом |
| **Nginx** | VPS (порт 80/443) | Веб-сервер, reverse proxy |
| **Supabase** | Облако | База данных, аутентификация |
| **Gemini / OpenAI** | Облако | AI (Gemini — основная для анализа исков) |
| **GitHub Actions** | GitHub | Автоматический деплой |
| **VPS** | 193.227.240.206 | Сервер, где все работает |

### Ключевые концепции

1. **Node.js** — позволяет выполнять JavaScript на сервере
2. **PM2** — обеспечивает стабильную работу приложения
3. **Nginx** — связующее звено между интернетом и приложением
4. **Next.js** — объединяет frontend и backend
5. **GitHub Actions** — автоматизирует деплой
